# ANSWER KEY — interview technical questions

1. The lookup-before-insert returns the existing Open session. Race: two starts both miss and both insert (no unique index on owner+parent+name+hash where status=Open). Fix: a partial unique index `WHERE status='Open'`, with 23505 → re-read and return the winner.
2. 404 via `SingleOrDefault` + `AppException(NotFound)` inside a query handler (J1). 404 doesn't confirm that the session exists.
3. `POST /public/shares/{token}/unlock {password}` → a short-lived signed cookie or token scoped to that share → `GET …/download` checks it. Keep accepting `?password=` for N months behind a deprecation header, and stop logging query strings on that route.
4. (a) Opt-in params: no `limit` gives the old array, `limit` returns `{items,nextCursor}`. (b) Keep the array and put the cursor in an `X-Next-Cursor`/`Link` header. Either way it's keyset on `(type,name,id)`.
5. The column is never assigned, so `WHERE "Version" = 0` always matches (verified: bigint, `ValueGenerated=Never`). Fix: `IsRowVersion()` → Npgsql `xmin` plus retry, or an atomic `UPDATE … SET used_bytes = used_bytes + @n WHERE used_bytes + @n <= quota_bytes`.
6. It's non-unique, case-sensitive, and includes `IsDeleted` as a key column instead of a predicate. Fix: `UNIQUE (owner_id, coalesce(parent_id, zero-uuid), lower(name)) WHERE NOT is_deleted`.
7. `parent_id → file_nodes`, `current_version_id → file_versions`, `share_links.file_node_id`, `direct_shares.file_node_id`, `file_versions.blob_id`. Purging a folder orphans its children; purging a file leaves live share links and direct shares pointing at nothing (the public link then 500s on `SingleAsync`), and blob references go stale.
8. A seq scan filtered on owner (or the owner-prefix index), `lower()` on every row, detoasting 1 MB of text, then sort plus offset. Names: `pg_trgm` GIN on `lower(name)`. Content: a `tsvector` GIN (M2).
9. Both pass `Status == Open` (line 33) and hash. With an existing blob, both call `AddReference`, `AddVersion` and `Reserve`, and both commit. With a new blob, the second one 500s on the unique content-hash index after writing to storage.
10. The file stays `PendingScan` forever, so download 409 "still being scanned". You'd detect it with an "oldest PendingScan age" metric or a check that `processing_jobs` are Queued > N minutes. Neither exists.
11. `ExecuteAsync` awaits each message serially. The delay blocks the only consumer, so poison messages (HEIC thumbnails) cost 30 s each and everything queues behind them.
12. Mark-then-delete with a grace period (`PendingDelete` state). Dedupe matches only `Live` blobs, and refcount changes are atomic SQL (M4).
13. `CopyAsync` marks copies Clean unconditionally, and `download?versionId=` serves any version while checking only the node's (current) status.
14. It fails open to a published key, so anyone can mint tokens. Required options with `ValidateOnStart`, and refuse the dev key outside Development (INC-005).
15. Bug side: users expect trash to revoke access, and there's a privacy expectation. Decision side: some products keep links alive until purge. Pick "trash revokes" and document it. At the least, the purge must revoke links, which it currently doesn't.
16. A single reusable read predicate or policy (`ReadableBy(userId)`), an authorization-matrix test across every read method × {owner, recipient, stranger}, and a CODEOWNERS or checklist rule for `OwnerId` predicates. Optionally an EF global query filter or RLS, with their trade-offs.
17. `arrayBuffer()` allocates 4 GB and the tab crashes or the upload never starts. Hash incrementally (a streaming SHA-256 in a Web Worker over `file.slice` chunks, e.g. hash-wasm), or drop the whole-file pre-hash and verify the server-side hash plus per-chunk hashes.
18. Each selection downloads the full file into memory (network and RAM). Object URLs pile up until reload, so memory grows by gigabytes. Fix: range or preview endpoints, thumbnails, and `URL.revokeObjectURL` in the effect cleanup.
19. (a) A model-builds test (J0 regression). (b) An authorization-matrix handler test for download, versions and public share (INC-003, M3). (c) A Testcontainers concurrency test for `complete` (M1). Layers: unit (no DB), handler + DB, handler + real Postgres.
20. An exception escaping `ProcessingWorker.ExecuteAsync` stops the host (default `StopHost`), so a scan-side DB blip takes down uploads and downloads. Fix: run workers as a separate deployment of the same image, add an error boundary per message, and consider `BackgroundServiceExceptionBehavior.Ignore` only together with alerting.
